## Fixed in this branch

### 1. Local server exposed the whole repository over HTTP (P0)

`platform/local-server/server.js` served any root-relative path, including
`platform/` source, `platform/data/db.json` (the user database), `.git/`,
`docs/`, and `qa/`. Replaced with an allowlist: the 7 production HTML pages,
`/assets/*`, capability-style gallery URLs, and (only with
`QS_ENABLE_DEV_ROUTES=1`) the dev UI + bag-reference files. Verified: source,
git, docs, qa, and db paths now 404.

### 2. Worker had no login/register throttling (P0)

The local server throttles auth (40-attempt/15-min IP ceiling + per-email
exponential backoff after 5 fails); the Worker accepted unlimited guesses.
Added the same policy on D1 (`auth_throttles` table, identical 429 body and
`Retry-After`), declared in `platform/schema.sql` plus migration
`004-auth-throttle.sql`. The Worker also self-creates the table on first auth
use, so existing deployments need no manual migration.

### 3. No cross-site (CSRF) defence on either backend (P0)

Session cookies are `SameSite=None` (preview iframes), so browsers attach them
to cross-site requests. Both backends now reject state-changing `/api/*` calls
carrying a foreign `Origin`/`Referer` with `403 ORIGIN_BLOCKED`. Requests with
no origin (curl, scripts, tests) still pass; `/api/auth/oauth/*` is exempt
because Apple POSTs from `appleid.apple.com` and that flow verifies its own
state/binding.

### 4. Portal bearer tokens could leak via Referer (P1)

Customer links carry `?t=` bearer tokens in the URL. Every HTML entry point
now sets `<meta name="referrer" content="no-referrer">` (matching the existing
`oauth-complete.html`), both APIs send `Referrer-Policy: no-referrer`, and the
header ships on all three hosting paths (local static handler, Cloudflare
`_headers` generated by `sync-public.js`, `vercel.json`).

### 5. Dead, misleading auth surface removed (P1)

- `login.html` was an unreferenced mockup whose fake submitter always
  "signed in" without touching any backend.
- `assets/js/login-auth.js` still described the pre-remediation recovery-code
  flow (including a branch that could display a reset secret) but had zero
  callers; `dashboard.html` redirects unauthenticated visitors to `index.html`.
- `assets/js/login-bag-ui.js`, `assets/css/login-bag.css`, and
  `docs/login-bag.md` only existed to support the above.

All deleted. Verified with repo-wide reference greps before removal.

### 6. Duplicate Worker entrypoint collapsed (P1)

`platform/cloudflare/src/index.js` was a ~1,800-line copy of `worker.js` that
had already drifted (two-route portal allowlist, legacy expiry semantics).
`wrangler.toml` points at `worker.js`, so `index.js` is now a thin re-export.
The existing `studio-security-worker.test.mjs` exercises both entries and
passes unchanged.

### 7. Dev bag-reference upload was reachable by default (P1)

Anonymous ~80 MB file hosting answered on any network-reachable server.
`/api/dev/bag-ref-*`, `/tmp/bag-reference/*`, `drop-bag-ref.html`, and
`preview-solar-login.html` now require `QS_ENABLE_DEV_ROUTES=1`; the tool page
says so in its banner. The startup log only advertises the drop URL when the
flag is on.

### 8. Portal event metadata unbounded/unfiltered (P2)

`POST /api/portal/event` stored arbitrary caller-supplied objects. Both
backends now apply a strict allowlist (`note` ≤ 500 chars; `sectionId`,
`choice`, `label` ≤ 120; numeric `index`, `progress`, `sectionIndex`).
The Worker's event-type allowlist was also brought to parity with local
(`pdf_download_requested`, `section_view`, `interest_recorded`,
`survey_requested`).

### 9. Worker-only dead endpoint removed (P2)

`POST /api/portal/open` existed only in `worker.js`, had no callers
(repo-wide grep), and returned full proposal snapshots to anyone with a link.
Removed; the portal GET route already serves snapshots with the same token
check. An unauthenticated POST now falls through to the staff-session gate.

### 10. Proposal status unconstrained (P2)

Both backends stored any caller-supplied `status` string. Create/update now
validate against the 10 known statuses
(`draft`, `internal_review`, `ready`, `sent`, `viewed`, `negotiation`,
`accepted`, `rejected`, `expired`, `archived`).

### 11. Worker link expiry could silently become "never" (P2)

`parseExpiryDays` returned `null` (non-expiring) for invalid input such as
negative days. Aligned with the local server: explicit future dates win,
anything invalid falls back to 30 days, capped at 365.

### 12. Task/gallery parity gaps (P2/P3)

- Worker task creation ignored `dueInDays` and never validated `proposalId`
  ownership (a user could attach tasks to another owner's proposal id). Both
  fixed.
- Worker gallery uploads buffered the whole body before the 900 KB check; a
  declared `Content-Length` over the cap is now rejected with 413 first.

### 13. Sign-in page depended on Google Fonts (P3)

`index.html` loaded Inter from Google Fonts, leaking sign-in visits to a third
party and breaking offline. It now embeds `@font-face` rules pointing at the
already-bundled `assets/fonts/inter-latin-*.woff2` files (weights 400–700).

### 14. QA preview server bound to all interfaces (P3)

`scripts/serve.js` listened on `0.0.0.0` while serving the working tree. It
now defaults to `127.0.0.1`; `HOST=0.0.0.0` restores LAN access explicitly.

## Deliberately not changed

- **No CSP / HSTS / frame-ancestors yet.** The app must keep working inside
  preview iframes and ships inline scripts/styles, so a strict policy needs a
  dedicated pass with reporting-mode validation first. Tracked as operator
  follow-up in the runbook, not silently dropped.
- **No refresh-token rotation.** Sessions are single bearer tokens; rotation
  would change client behaviour and needs a design decision first.
- **`docs/studio-audit-findings-2026-10-04.md` untouched.** It records the
  state at audit time; this document records what changed since.
- **Browser suites: NOT RUN.** This sandbox has no system browser libraries
  (Playwright Chromium exits 127 for `libnspr4`), and this repo has no CI —
  there is no `.github/workflows` directory and nothing executes tests
  automatically. The browser suites are not "expected to pass in CI"; they
  are unverified by this change. See the runbook for options.
